# Ciclo 05 — Pricing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` to implement independent tasks after contracts and database boundaries are frozen. Steps use checkbox syntax.

**Goal:** Deliver App 02 product, combo and channel pricing with exact calculations, owner-scoped persistence, recipe-cost integration and immutable simulation history.

**Architecture:** Keep calculation in a new pure `@donos/domain-pricing` package; use versioned Zod contracts, the existing Fastify API and Postgres/RLS, and the existing Vite Precificação shell. The backend enforces `pricing_core`; recipe cost reuses the existing recipe service and separately enforces `inventory_core`. The UI never calculates authoritative money or accesses database tables.

**Tech Stack:** Existing TypeScript, pnpm workspaces, Zod 4, Fastify 5, PostgreSQL `numeric`, React/Vite, Vitest and Playwright. No new dependency is planned.

**Spec:** `docs/superpowers/specs/2026-10-16-pricing-design.md`

## Global Constraints

- Respect DONOS Next V3 DEC-001 through DEC-013 and criteria T-15 through T-18.
- `organization_id` is the primary boundary; validate owner and `restaurant_id` in API and RLS. No employee profiles/RBAC.
- Money and quantities are decimal strings/integers/ratios; no critical `number` arithmetic. Price suggestion rounds up to BRL cent and all output metrics recalculate from that final price.
- App 02 works with `pricing_core` and manual cost alone. Recipe cost integration requires same-owner `inventory_core`, location and validated recipe state.
- Recipe/stock cost remains authoritative in App 01. Never query its tables from the browser or duplicate its valuation algorithm.
- Simulations are append-only snapshots. Writes are idempotent, transactional and audited.
- Never touch legacy, production, old Vercel/domains, billing, paid integrations or WhatsApp. The founder explicitly authorized Cycle 05 tests and additive migrations only on Supabase DONOS Next DEV project `kfthwjrvgslnsjigqnyc` on 2026-10-16; no other remote target is authorized.

- `PricingMoneyString`: canonical BRL amounts using `InventoryValueStringSchema` precision (up to 26 integer digits and 12 fraction digits). Percentages and quantities use their existing canonical schemas. Exact internal products/sums use bigint rationals; only displayed quote price rounds upward to cent.
- `ExactMoneyRatio`: `{ numerator: CanonicalUnsignedIntegerString; denominator: CanonicalPositiveIntegerString }`, value in BRL is `numerator / denominator / 10^12`. GCD-reduced; each integer string is bounded to 256 digits, with explicit `NUMERIC_RANGE` on overflow. This is a pricing/recipe wire contract and does not import inventory-domain types.
- `PricingCostComponent`: `{ componentPath: string[]; role: 'ingredient'|'packaging'; costPerFinalUnitExact: ExactMoneyRatio }`. Recipe components and total reconcile exactly as rational values; the existing rounded `costPerFinalUnit` remains display-only. Adapt manual ingredient to a reserved stable path and each package to `[packageId]`. Recipe values are scaled to one sale with rational arithmetic; do not round components.
- `PricingPackagingInput`: `{ id:string; name:string; costPerSale:PricingMoneyString }`; map manual packaging to the stable path `[id]`. Manual ingredient cost and manual packaging stay separate so the UI cannot add packaging invisibly to both cost buckets.
- `ManualCostSourceInput`: `{ kind:'manual'; ingredientCost:PricingMoneyString; currency:'BRL' }`; `RecipeCostSourceInput`: `{ kind:'recipe'; recipeId:string; locationId:string; quantityPerSale:QuantityString }`, where quantity uses the current recipe output unit and scales the recipe cost/components to one sale.
- `PricingVariantCostSource`: manual `{ kind:'manual'; ingredientCost: PricingMoneyString; currency:'BRL'; updatedAt:string }` or recipe link `{ kind:'recipe'; recipeId:string; locationId:string; quantityPerSale:QuantityString }`. A variant stores a link only, never stale recipe cost.
- `PricingCostSourceSnapshot`: manual `{ kind:'manual'; ingredientCost:PricingMoneyString; currency:'BRL'; updatedAt:string }` or recipe `{ kind:'recipe'; recipeId:string; recipeVersionId:string; locationId:string; quantityPerSale:QuantityString; calculatedAt:string; unitCostExact:ExactMoneyRatio; unitCostDisplay:PricingMoneyString; components:PricingCostComponent[] }`. The pricing contract owns this wire DTO and does not import recipe-domain types. Every simulation refreshes recipe cost through the central recipe service; historical snapshots retain the version/cost used.
- `PricingVariantSnapshot`: `{ variantId:string; name:string; listPrice:PricingMoneyString; costSourceSnapshot:PricingCostSourceSnapshot; packaging:PricingPackagingInput[]; otherVariableCost:PricingMoneyString }`. Every simulation stores this immutable data for the selected variant; recipe snapshots retain the current validated version, location, `quantityPerSale` and exact component costs. App 02 packaging remains a per-sale amount outside the recipe quantity multiplier.
- `PricingComboComponentCostSnapshot`: `{ variantSnapshot:PricingVariantSnapshot; quantity:QuantityString; costComponents:PricingCostComponent[]; replacedPackagingPaths:string[][] }`. A combo simulation stores one snapshot for every configured component, including its exact recipe/manual source and package overrides. `PricingSimulation.variantSnapshot` is non-null for a single variant and null for a combo; `componentCostSnapshots` is empty for a variant and complete for a combo.
- Approved combo price adds positive `listPrice` to `CreatePricingComboInput`, `UpdatePricingComboInput` and `PricingCombo`; quote current-price metrics use it, and `comboSnapshot` freezes it for history. - `PricingComboCostInput`: `{ components:Array<{ variantId:string; quantity:QuantityString; costComponents:PricingCostComponent[]; otherVariableCostPerSale:PricingMoneyString; replacedPackagingPaths:string[][] }>; exclusivePackaging:PricingPackagingInput[] }`. Component costs come from the selected cost-source snapshot; only package paths explicitly listed for replacement are excluded. Manual ingredient/package paths are stable IDs.

- `PricingQuote`: `{ status:'available'|'unavailable'; reason:string|null; suggestedPrice:PricingMoneyString|null; costBuckets:{ingredients:PricingMoneyString;packaging:PricingMoneyString;otherVariable:PricingMoneyString}; totalVariableCost:PricingMoneyString; currentPriceMetrics:{netRevenue:PricingMoneyString;contributionMargin:DecimalString;cmv:DecimalString}|null; suggestedPriceMetrics:{netRevenue:PricingMoneyString;contributionMargin:DecimalString;cmv:DecimalString}|null; rateBreakdown:Array<{rateId:string;base:PricingMoneyString|null;amount:PricingMoneyString}> }`.
